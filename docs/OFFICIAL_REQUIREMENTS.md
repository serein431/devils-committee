# 官方参评要求总表

更新日期：2026-07-24。本文根据团队收到的五张官方要求截图整理，后续开发、文书、演示和提交前检查均以此为准。

## 18 PandaAI

### 必须完成

- 以 A2A Remote Agent 形式提交，自行托管智能体服务。
- 提供公开可访问的 Agent Card URL，Agent Card 内容完整、真实。
- 支持 A2A 协议调用，能处理平台发送的自然语言任务。
- 服务在评审期间保持在线，单次任务总响应时间不超过 20 分钟。
- 输出过程和最终结果清晰、可解释。
- 不得绕过平台权限访问未授权数据、接口或第三方服务。
- 模型统一使用 DeepSeek V4 Pro。
- 至少完成 3 个示例任务测试。
- 所有投资相关输出必须包含风险提示。

### 提交材料

- Agent 名称、简介和团队信息。
- Agent Card URL、智能体服务地址和鉴权方式。
- 作品说明文档，以及示例问题与预期输出。
- 使用的数据、数据 Skills 和研究 Skills 清单。
- 文档需说明使用场景、系统结构、Skills 调用方式和结果展示。
- 演示视频应完整展示主要流程。
- GitHub 仓库需允许评审访问；不能提供仓库时，将完整代码发送至 `code@pandaai.online`。

### 当前项目需要修正

- 现有 Agent Card、A2A、SSE 和风险检查可以保留，但仍需公网地址和稳定托管。
- 模型配置必须固定到官方 DeepSeek V4 Pro Endpoint，不能只写“任意 OpenAI 兼容模型”。
- 现有三个示例中包含 NVDA、TSLA；A 股优先版本应改为三个真实 A 股任务，并保存真实请求与输出。
- 当前 GitHub 仓库为私人仓库，需要给评审访问权限，或按要求发送完整代码。
- 数据和 Skills 清单必须来自真实运行记录，不能把模拟结果写成已接入。

## 04 Qoder

需要回答两项：

1. 项目解决什么问题，目标用户是谁。
2. 描述人和智能体共同开发的过程：AI 承担哪些角色，人负责哪些判断，双方如何分工。

截图中没有要求必须提交录屏或开发截图。若团队已有实际开发记录，可以作为补充材料，但不能写成官方硬要求。

## 05 智能少年

### 必答

- 用 100–300 字说明为什么由这支团队做：与成员的兴趣、经历或优势有什么关系。
- 说明最近几天是否有真人使用，使用者是谁，反馈是什么。

### 可选

- 若参加“为 10 后而造”特别奖，描述一个 10 岁孩子或家长实际使用产品的情景。

当前项目需要补真人试用记录和原话。若没有面向儿童或家长的真实功能，不应勉强填写特别奖内容。

## 15 度小满

需要准备以下八项材料：

1. 明确产品服务的具体理财用户群体。
2. 说明他们在理财过程中遇到的真实困扰，以及得出判断的依据。
3. 说明 AI 理财建议的生成过程、判断框架和异常情况处理，包括风险提示规则与人工介入方式。
4. 列出全部 AI 能力、数据来源和模型，并说明组合使用方式。
5. 分别写明已实现功能、尚未完成部分和目前最大的困难。
6. 介绍全部团队成员及分工。
7. 提供演示视频链接和项目访问链接。
8. 可选：说明希望度小满提供的具体支持。

本项目必须坚持“帮助用户理解证据，不提供买卖指令”。所有真实数据、演示假设和预计算结果要分别标明。

## 07 小红书

需要回答四项：

1. 项目是什么，解决谁的问题。
2. 希望通过什么内容形式让更多人看到。
3. 开发过程中吸收了哪些小红书用户或作者的建议、反馈与启发。
4. 希望连接哪些资源、产品或合作伙伴。

需保存帖子链接、发布时间、评论区反馈、团队回复和由反馈带来的实际修改。金融内容只展示教育用途、开发过程和风险分析，不发布选股结论或收益承诺。

## 提交前统一检查

- [ ] DeepSeek V4 Pro 真实调用通过，并保存不含密钥的测试记录。
- [ ] PandaData 与选定 QuantSkills 均有真实运行记录。
- [ ] 三个 A 股示例任务可重复运行，输出含数据来源和风险提示。
- [ ] Agent Card 与 A2A 服务可从公网访问，完整检查通过。
- [ ] 评审期间的服务托管、健康检查和故障恢复方案可用。
- [ ] GitHub 访问方式或邮件交付方式已经确认。
- [ ] Qoder 的两个官方问题已经完整回答；开发截图或录屏仅作为可选补充。
- [ ] 真人试用记录、反馈原话和使用人数已经填写。
- [ ] 小红书帖子链接、互动记录和实际修改已经填写。
- [ ] 演示视频、项目访问链接、团队成员和分工已经填写。
