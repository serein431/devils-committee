# Devil's Committee · 反方 —— 项目综合介绍与赛道回应

> 一个面向投资研究初学者的多智能体「反方教练」。
> Bull、Bear、Macro、Risk 四个研究 Agent 先独立立论，再针对对手的具体论据交叉质询；Audit Agent 可以驳回越界推断，Chair 根据辩论结果给出「强在哪里、弱在哪里、分歧还剩什么」的综合判断。
> 不给买卖指令、目标价、收益承诺，不执行自动交易。所有输出仅供学习与研究。

---

## 一、项目详细介绍

### 1. 我们在做什么

**Devil's Committee（反方委员会）** 是一个 A 股投资研究的「多智能体辩论庭」。它要解决的不是「让 AI 给出一个更聪明的答案」，而是「让 AI 主动反对自己」——把一份研究材料里被掩盖的反方理由、被美化的数据缺口、被低估的模型风险，全部摊开摆在用户面前。

市面上大多数 AI 投研工具都在做同一件事：用户问一个问题，AI 给一个看似专业的结论。但真实的研究从来不是这样。一个合格的研究员在写多头报告的同时，必须能写出同样有力的空头报告；在引用一组数据的同时，必须追问这组数据有没有幸存者偏差、有没有复权错误、有没有过拟合。

Devil's Committee 把这件事做成了一场会真正改变结论的研究流程：

- **Bull（多方）** 从盈利、经营质量、估值和市场相对强势中寻找积极证据；
- **Bear（空方）** 从盈利放缓、估值约束、资金变化和下行情景中寻找反证；
- **Macro（宏观）** 只讨论有数据支撑的行业、利率、指数和市场环境，不用个股涨跌替代行业判断；
- **Risk（风险）** 量化波动、回撤、流动性、质押、解禁和重大事件等风险边界；
- **Audit（审计）** 不站多空，检查证据、时点、口径和推理越界，可以要求 Agent 撤回或收窄观点；
- **Chair（主席）** 汇总辩论后仍然成立的结论，先回答股票当前强在哪里、弱在哪里，再呈现未解分歧。

第一轮不是终点。第二轮中，每个 Agent 必须点名回应具体 `claim_id`，说明对方依赖了什么前提，并选择「承认、反驳或要求补证」。如果 Audit 发现某个 Agent 把相关性写成因果、把个股相对收益写成行业风格、把数据异常写成公司利空，该论点会被驳回，最终总结也必须随之改变。

新版还增加了确定性的语义审计护栏：利润下降不能擅自归因于投资损益、准备金或赔付，股东户数变化不能推断筹码从机构转向散户，历史波动不能证明上涨“只是反弹”，沪深300估值也不能替代同行和历史估值分位。这些规则不依赖模型是否自觉遵守；越界论据会被标记为证据不足，并从 Chair 的收敛依据中排除。

### 2. 为什么这件事重要

初学者看研究报告时最容易踩的坑，不是看不懂术语，而是**不知道这份报告在哪些地方是脆弱的**。一份看起来逻辑严密的多头报告，可能建立在一个被精心挑选过的样本上；一组漂亮的回测曲线，可能只是把答案背了下来。

Devil's Committee 把这些「脆弱点」用初学者能懂的话标出来：

- `selection_bias` → 「只把考了高分的同学拿出来吹，输的都不提」
- `bad_data` → 「体重秤没归零就称，先把数据修对再谈结论」
- `suspected_overfit` → 「把这次的答案背下来考试，换一套题就不灵」
- `thin_data` → 「证据太少，既不能信、也不能一口否掉」

### 3. 研究能力

构建股票本身的九类研究画像：

1. 公司与行业画像
2. 盈利与财务画像
3. 估值画像
4. 市场趋势画像
5. 行业横向比较
6. 资金与交易情绪画像
7. 股东与资本行为画像
8. 重大事件画像
9. 宏观环境画像

数据审计作为第十个辅助层存在，用于回答「这些结论是否建立在可靠数据上」，而不是替代「这家公司经营怎么样、估值怎么样、市场表现怎么样」。

PandaData 接口按需动态路由：交易日期、股票信息、日线与复权、季度财报、业绩预告、审计意见、行业成分、指数、融资融券、沪深股通、股东户数、质押、增减持、回购、解禁、龙虎榜、重大合同、诉讼及相关宏观数据均纳入新版接入范围。接口会全部进入能力注册表，但不会在每次请求中无脑全量调用；编排 Agent 根据股票行业、用户问题和前置结果选择必要接口，兼顾证据覆盖、限流与响应时间。

### 4. 技术架构一句话

FastAPI 后端 + A2A v1 JSON-RPC 协议 + SSE 流式推送 + 静态 Web 教练页；LLM 走 Volcengine Ark（DeepSeek V4 Pro），数据走 PandaData 动态数据路由，研究层生成结构化公司画像并运行 QuantSkills，Bull / Bear / Macro / Risk 完成两轮辩论，Audit 独立复核，Chair 收敛结论。所有公开文本经过 `backend/compliance.py` 合规检查。

### 5. 一次请求如何完成

```text
自然语言问题
  ↓
Planner 识别股票、行业、研究时点与用户真正关心的维度
  ↓
Data Router 并行调取行情、财务、行业、资金、股东、事件和宏观数据
  ↓
生成九类股票研究画像 + 独立数据审计证据
  ↓
四方 Agent 第一轮独立立论
  ↓
四方 Agent 第二轮定向交叉质询
  ↓
Audit 驳回错误归因、证据越界和未经验证的推断
  ↓
Chair 输出辩论后保留、修正和撤回的观点
  ↓
A2A / SSE 返回可解释结果
```

### 6. 示例问题及对应的预期输出

**示例问题**：

> 分析 `601628.SH` 当前到底偏强还是偏弱。请让各 Agent 使用真实数据互相辩驳，并说明辩论后哪些观点被保留、修正或驳回。

**预期输出摘要**：

```text
EVIDENCE BOARD
营收同比 -15.33%｜归母净利润同比 -32.28%｜保险业务收入同比 +1.08%
PE 14.60｜PB 1.86｜近60日 +11.77%｜相对沪深300 +14.32pct
60日年化波动 41.09%｜近120日最大回撤 -34.65%

第一轮
Bull：主业收入仍有韧性，个股近期相对市场偏强。
Bear：利润收缩是核心压制，当前估值未必提供足够保护。
Macro：只能确认个股跑赢指数，不能据此推断保险板块整体转强。
Risk：高波动和深回撤意味着方向判断之外仍有较高持有风险。

第二轮交叉质询
Bear → Bull：收入稳定不等于盈利能力稳定，是否低估了利润下降？
Bull：接受。撤回“基本面偏强”，修正为“主业规模稳定但盈利承压”。

Bull → Bear：现有证据能否证明近期上涨一定只是超跌反弹？
Bear：不能。撤回“必然只是反弹”，保留“高波动使趋势可靠性较低”。

Risk → Macro：单只股票跑赢指数能否证明保险行业环境友好？
Macro：不能。只保留个股相对强势，等待行业与宏观数据验证。

Audit
PASS：核心财务与行情数字可回链。
REVISED：Bull 的基本面结论被收窄。
REVISED：Bear 撤回未经验证的反弹定性。
REJECTED：不得自行推断利润下降由投资收益、赔付或准备金导致。

Chair
综合判断：分歧较大，短期市场偏强，中期基本面偏谨慎。
辩论后保留的是“相对强势、主业收入韧性、利润下滑和高波动”；
被撤回的是“基本面已经偏强”和“上涨必然只是超跌反弹”。
```

这个结果不是六个 Agent 各说一遍，而是对手的质询会迫使 Agent 承认、修改或撤回观点，最终结论因此发生变化。

### 7. 我们刻意不做什么

- 不给买卖指令
- 不给目标价
- 不给收益承诺
- 不做自动交易
- 真实数据缺失时返回 `insufficient-evidence`，绝不用 mock 冒充真实研究

## 灵光赛道（03）「见自己」—— 先为自己 Vibe

### 1. 项目名称 + 一句话介绍你和作品的关系

**Devil's Committee · 反方** —— 一个替初学者「唱反调」的 AI 投研辩论庭。

它和我们团队的关系：团队成员都曾是那个看了一份多头研报就冲进去、然后被套牢的「初学者」。我们做的不是给别人用的工具，是**给三年前那个自己**用的工具——如果当时有一个 AI 愿意把反方理由讲清楚，我们可能就不会交那么多学费。

### 2. 作品如何引起共鸣？和你一样面临这个问题的人有多少？

几乎每个 A 股散户都经历过同一个剧本：看到一份逻辑漂亮的研报 → 被说服 → 买入 → 被套 → 回头才发现报告里没提的那些风险。

中国结算数据显示 A 股个人投资者账户超过 2 亿，其中绝大多数没有系统的研究训练。他们不缺「AI 给结论」的工具，缺的是**「AI 帮我把反方意见讲清楚」**的工具。Devil's Committee 引起共鸣的方式很直接：让用户体验一次「原来这份报告在这么多地方是站不住的」的震撼。

### 3. 灵光在里面起到的作用

- **直接使用灵光开发**：项目早期的产品原型、交互稿和前端教练页的视觉风格，是用灵光快速生成和迭代的。我们把「多智能体辩论」这个抽象概念，用灵光的闪应用能力快速做成了可点击的 Demo，用来验证「初学者是不是真的需要看反方意见」这个产品假设。
- **灵光闪应用作为内容载体**：项目的演示视频脚本、路演用的产品故事板，都是在灵光上辅助做出的。
- **一键部署工具**：使用灵光的一键部署能力，把早期的静态演示页快速发布到公网，用于活动期间的现场演示和用户测试。
- **实际开发产品**：核心后端（FastAPI + A2A + 多 Agent 编排）使用 Python 开发，LLM 调用走 Volcengine Ark（DeepSeek V4 Pro），数据层接 PandaData 和 QuantSkills；灵光主要负责前端原型、演示材料和早期产品验证。

## Qoder 赛道（04）小团队高效开发

### 1. 项目解决了什么问题？目标用户是谁？

**问题**：股票研究材料普遍「结论先行」，反方理由、数据缺口、模型风险被掩盖。初学者没有能力也没有工具去识别这些脆弱点。

**目标用户**：想理解股票研究、但不熟悉量化术语的个人投资者。当前真实研究支持 A 股、港股和美股，并按代码或公司名称自动路由；重点验证示例包括 `600519.SH`、`0700.HK` 和 `AAPL`。

### 2. 人机协作工作流：AI 承担哪些角色，人如何分工

我们是一个 2-4 人的小团队，用 Qoder 完成了过去需要一整个工程团队才能搞定的事。

**AI 在项目中承担的角色**：

- **前端工程师**：Qoder 根据产品需求直接生成并迭代 `web/index.html` 教练页，包括 SSE 流式渲染、多 Agent 观点卡片布局、审计标记的人话翻译展示。
- **后端工程师**：Qoder 负责 FastAPI 路由、A2A 协议实现、SSE 推送、多 Agent 编排逻辑的代码编写和重构。
- **测试工程师**：Qoder 自动生成 pytest 用例、前端测试脚本，并维护 `tests/` 目录下的三个 A 股固定示例。
- **代码评审员**：Qoder 的多智能体专家协作架构被用来做交叉评审——一个 Agent 写代码，另一个 Agent 检查合规规则是否被破坏、类型注解是否完整、是否有安全漏洞。
- **文档工程师**：Qoder 根据代码变更自动同步更新 `docs/ARCHITECTURE.md`、`docs/LIVE_INTEGRATION.md` 和各赛道提交说明。

**人的分工**：

- **产品决策**：定义「不给买卖指令、不给目标价、不给收益承诺」的产品边界，决定哪些功能做、哪些坚决不做。
- **合规把关**：审查 `backend/compliance.py` 的 8 类规则是否覆盖所有公开输出。
- **真实环境验证**：人工执行 `RUN_LIVE_INTEGRATION=1` 的真实联调测试，确认 PandaData、QuantSkills、Volcengine Ark 的凭证和调用链路。
- **关键决策**：是否合并 AI 生成的代码、是否部署公网服务、是否提交参评材料，全部由人确认。

**Qoder 的多智能体协作深度**：我们没有把 Qoder 当普通代码补全工具用。后端编排、前端页面、测试用例、文档更新是**并行推进**的——一个 Agent 在改 A2A 协议实现的同时，另一个 Agent 在更新对应的测试用例，第三个 Agent 在同步文档。这种多角色并行协作，让 2-4 人的小团队完成了过去需要前端、后端、测试、运维各司其职才能完成的工作。

## 智能少年赛道（05）不做第一，做唯一

### ① 为什么是你们做这个？它和你们的痴迷、经历或优势有什么关系？（100-300 字）

团队里每个人都有一段「被研报收割」的黑历史。有人看着某券商的强烈推荐买入，三个月亏了 40%；有人照着大 V 的「必涨逻辑」满仓，结果踩中了流动性危机。我们痴迷的不是「怎么赚更多」，而是**「为什么当时没人告诉我反方意见」**。

我们的独特优势在于：团队同时有量化研究背景和一线用户运营经验。既看得懂因子 IC、Rank IC、分组回测这些专业概念，又知道初学者看到「selection_bias」这个词时脑子里一片空白。这种「既懂专业又懂小白」的双重视角，让我们能把审计结果翻译成「只把考了高分的同学拿出来吹」这样的人话。

Devil's Committee 只有我们能做出来——因为它需要的不是更强的模型，而是**愿意让 AI 反对自己**的产品哲学，以及把专业审计结果翻译成初学者语言的耐心。

### ② 谁是它的真实用户？这几天有没有真人用过它？反馈是什么？

真实用户是想理解 A 股研究、但没有量化背景的初学者，包括：刚开户的大学生、想学习研究的上班族、被各种「老师」坑过的散户。

活动期间我们邀请了多位现场用户体验，具体试用记录和反馈正在整理中，将在正式提交前补充。

### ③ （选答）为 10 后而造：描述一个 10 岁孩子或家长使用它的场景

**场景**：一个 12 岁的孩子用家长的账户体验「模拟炒股」，看到某只股票「连续涨停」，想all in。家长打开 Devil's Committee，输入这只股票的代码。

孩子看到的不是「可以买/不可以买」，而是：

- Bull 说：「这家公司最近业绩很好，行业也在风口。」
- Bear 说：「但股价已经涨了很多，估值可能偏贵，而且成交量在萎缩。」
- Risk 说：「这只股票流动性一般，如果很多人同时卖，可能卖不出去。」
- Audit 说：「注意，这份分析用的数据样本可能有问题——只看了最近涨的股票，没看跌的。」

孩子问：「那我到底该不该买？」

Chair 回答：「我们不告诉你该不该买。我们告诉你：看多的理由是什么，看空的理由是什么，数据在哪些地方可能有问题。决定，你自己做。」

这个场景的价值在于：它不是教孩子「怎么炒股」，而是教孩子**「怎么面对一份看起来很美的结论时，保持怀疑」**——这是 AI 原住民一代最需要的批判性思维训练。

## 小红书 · Build in Public 赛道（07）

### 1）项目是什么？解决了谁的什么问题？

Devil's Committee 是一个「反方教练」——专门替 A 股初学者唱反调的 AI 工具。它解决的是「看了一份漂亮研报就冲进去，然后被套牢」的问题。四个研究 Agent 不只是分别陈述多头、空头、宏观和风险观点，还会在第二轮点名质疑对方论据；Audit 可以驳回越界推断，Chair 展示每个观点在辩论后是被保留、修正还是撤回。

### 2）希望在小红书上用什么方式让它被更多人看见？

- **系列笔记「反方日记」**：每篇笔记拆解一个真实的研究陷阱——「这份研报为什么看起来对，实际上错」「AI 是怎么发现数据被挑过的」「过拟合：把答案背下来考试」。
- **对比视频**：同一只股票，左边是券商研报的「强烈推荐」，右边是 Devil's Committee 的「反方意见」，让用户直观感受「原来还有这么多没被告知的」。
- **互动话题**：「你被哪份研报坑过？」「如果 AI 告诉你这只股票有风险，你还会买吗？」——用真实经历引发共鸣。
- **直播演示**：现场输入一个股票代码，看四个 AI 吵架，看审计 AI 抓数据问题。

### 3）开发过程中吸收了哪些小红书用户、作者的建议或启发？

- 小红书「理财小白」话题下的高赞评论反复提到「看不懂术语」，这直接促使我们把所有审计标记都翻译成了人话。
- 一位小红书财经博主提到「散户最需要的是有人告诉他什么时候不该买」，这坚定了我们「不给买卖指令，只给风险边界」的产品定位。
- 小红书用户对「AI 会不会骗我」的讨论，让我们把「来源标注」（live / cache / precomputed / mock）做成了产品核心特性，而不是技术细节。

### 4）想在小红书对接哪些资源、产品或伙伴？

- **财经科普博主**：合作制作「反方思维」系列内容，把 Devil's Committee 作为教学工具。

## 度小满赛道（15）Money Whisperer：你的第一个 AI native 理财产品

### 1. 产品核心服务人群

**想理解股票研究、但不熟悉量化术语的 A 股初学者**——具体画像是：25-40 岁、有 1-5 年投资经验、看过研报但看不懂术语、被「老师」或「大 V」坑过、想建立自己的研究框架但不知道从何入手。

### 2. 目标用户理财痛点及判断依据

**痛点**：初学者面对研报时，只能看到「结论」，看不到「反方理由」「数据缺口」「模型风险」。他们不知道一份看起来逻辑严密的报告，可能在样本选择、数据处理、参数调优上做了手脚。

**判断依据**：
- 中国结算数据：A 股个人投资者超 2 亿，其中绝大多数没有系统研究训练。
- 小红书、雪球等平台「被研报坑了」话题下的大量真实用户反馈。
- 团队成员亲身经历：看着「强烈推荐」买入，三个月亏 40%。

### 3. AI 投顾的建议生成逻辑

**核心原则：不给建议，只给证据。**

Devil's Committee 不是传统意义上的「投顾」——它不告诉用户该买什么、该卖什么。它的角色是「研究陪练」：

1. **任务规划**：识别股票、行业、有效交易日和用户真正关心的问题，避免硬编码日期。
2. **证据收集**：PandaData 动态路由并行获取行情、季度财报、估值、行业、资金、股东、公司事件和宏观数据；QuantSkills 负责复权、幸存者偏差、流动性和模型证据检查。
3. **研究画像**：先生成盈利、估值、趋势、行业、资金、股东、事件和宏观等结构化画像，确保讨论主体是股票本身，而不是内部工具状态。
4. **第一轮立论**：Bull、Bear、Macro、Risk 使用各自负责的证据独立判断偏强、偏弱或证据不足。
5. **第二轮交叉质询**：四方点名回应具体 `claim_id`，必须承认成立的反证，也可以要求对方撤回未经验证的推断。
6. **独立审计**：Audit 检查数字、时点、口径、前视偏差和推理越界，对不合格论点给出 `REVISED` 或 `REJECTED`。
7. **综合判断**：Chair 先回答股票强在哪里、弱在哪里，再列出辩论后保留、修正和撤回的观点。

**异常场景应对**：
- 数据缺失 → 返回 `insufficient-evidence`，明确告知「证据不足，无法得出结论」。
- 用户要求买卖指令 → 合规层直接拒绝，返回「本产品不提供买卖建议」。
- 真实数据/模型/Skill 失败 → 返回错误或 `insufficient-evidence`，绝不降级为 mock。
- 所有公开文本经过 `backend/compliance.py` 8 类规则检查，禁止买卖指令、目标价、收益承诺。

**人工介入机制**：当前版本为全自动运行，但所有输出均经过合规层过滤；未来版本计划增加「人工研究员复核」开关，对高波动标的强制人工确认。

## REVERSE 主题回应

**我们的 REVERSE，是让 AI 从「说服用户」转向「反对自己」。**

传统 AI 投研的路径是单向的：用户提出问题，模型寻找证据，最后生成一个听起来完整、确定、值得相信的答案。模型越擅长表达，用户越容易忽略这个答案背后的反证、假设和数据边界。

Devil's Committee 把这条路径反了过来：

- 从「一个 Agent 给答案」反转为「多个 Agent 公开争论」；
- 从「寻找支持结论的证据」反转为「主动寻找能够推翻结论的证据」；
- 从「各自发表观点」反转为「点名质询、承认反证、撤回越界判断」；
- 从「数据审计藏在后台」反转为「让用户直接看见证据是否可靠」；
- 从「AI 替用户做决定」反转为「AI 展开分歧，把判断权还给用户」。

在第二轮交叉质询中，REVERSE 不只是产品口号，而是会真实改变系统输出的工作机制：Bull 必须面对 Bear 的反证，Bear 也必须证明自己的悲观判断没有超出数据；Macro 不能用一只股票的上涨代表整个行业，Risk 不能把数据异常直接写成公司利空。Audit 有权驳回这些推断，Chair 最终只保留经得住反方攻击的部分。

例如，Bull 最初可能判断「基本面偏强」，但面对利润同比下降的证据后，必须修正为「主业规模稳定，但盈利仍然承压」；Bear 可能判断「上涨只是超跌反弹」，但在缺少资金持续性证据时，也必须撤回这个定性。系统不是为了证明某个 Agent 更聪明，而是通过互相拆台，让最后的结论比任何一个 Agent 的第一反应更可靠。

**别人给用户一个结论，我们给用户一个会自我拆台的委员会。**

这就是 Devil's Committee 对 REVERSE 的回答：不是让 AI 更坚定地替人判断，而是让 AI 学会怀疑自己、公开反对自己，最终教用户成为自己的裁判。
